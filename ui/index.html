About

BlueLine — Universal Security & Reliability Assessment Platform

Offline-first. No target data or scan results ever leave this machine. All processing happens in the local BlueLine engine running on 127.0.0.1.

Data & Storage

Scan history is stored locally in your OS's per-user application-data directory (e.g. %LOCALAPPDATA%\BlueLine on Windows) — never next to wherever the BlueLine engine happens to be run from.

Known Limitations (this build)
  • JavaScript/TypeScript, Java, Go, Ruby, PHP, Rust, Kotlin, Swift, and Scala analysis are heuristic/pattern-based, not full parsers.
  • C/C++ source analysis is experimental pattern-matching on a small set of unsafe calls.
  • Binary analysis: ELF is fully parsed and validated; PE gets header metadata only (no imports); Mach-O gets string extraction only.
  • No analyzers yet for niche languages (Dart, Elixir, Haskell, C#, Perl, etc.) — detected, but marked unsupported.
  • Dependency checks use a small local curated sample, not a live vulnerability feed.
  • Fuzzing is black-box (no code-coverage feedback loop).
  • Web/API analysis is passive (headers/cookies/CORS/transport) — no auth or injection testing against live endpoints.
